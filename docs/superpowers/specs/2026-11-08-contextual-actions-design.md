# Контекстные действия «Что дальше»

Пользователь выбрал вариант 2 и разрешил реализацию 08.11.2026: после основных
действий показывать результат и следующие подходящие действия, сохранив ручные
меню и все проверки установщика. Основной адресат — начинающий администратор.

Рассмотрены: переходы только после быстрой проверки; контекстные переходы во всех
основных разделах (выбрано); отдельный сквозной мастер с перестройкой главного меню.

## Поведение

- После проверки, плана, аудита, веб-проверки и настройки: краткий вывод,
  объяснение недостающих данных и переход к проверке, плану либо автообновлению.
- Поддерживаемый профиль позволяет начать подготовку, но не обещает готовность
  к установке. Отсутствующая веб-проверка выполняется внутри автообновления;
  отдельный полный аудит не обязателен.
- Неподдерживаемый/неизвестный профиль и несогласованные RPM не открывают быстрый
  переход к установке. Нужны конкретная причина и повтор проверки после исправления.
- После обновления/отката: результат, сведения именно об этой операции,
  журнал, ручная проверка Битрикса и подходящие действия восстановления.
- Ошибка до установки не должна связываться с чужой/старой последней сессией.
- Выбранный сайт передаётся следующему действию, но заново валидируется штатным
  обработчиком. Результат проверки не является разрешением пропустить preflight.
- Enter/0 возвращают в ручное меню, EOF завершает навигацию. Опасные действия
  выбираются явно; штатные подтверждения остаются отдельными.
- CLI и unattended не получают дополнительных вопросов. Номера ручных меню
  сохраняются. Сборка/подпись выпусков не перестраиваются в этой итерации.

## Реализация

Один общий интерактивный цикл поверх существующих CLI-обработчиков. Отдельная
оценка готовности использует php_version_route, profile_check и проверку RPM,
а не код возврата диагностической команды или цвет предупреждения.

Дочерняя команда передаёт выбранный сайт и идентификатор/состояние собственной
сессии через выделенный дескриптор во временный приватный файл родителя.
Данные разбираются по разрешённым ключам, никогда не исполняются. Обычный CLI
не включает этот канал. Навигация не меняет предохранители установки/отката.

Резервную копию создаёт и проверяет администратор; скрипт получает подтверждение.
Проверка веб-PHP не подтверждает админку, формы, БД и остальные функции приложения.
