## Настоящие RPM, Apache и восстановление

Приёмочные прогоны выполнены в одноразовых контейнерах CentOS 7 x86_64
с настоящими RPM, Apache 2.4.6, prefork и mod_php. Для распознавания профиля
создан тестовый `/etc/httpd/bx`; полноценный BitrixEnv и сам Битрикс в эти
контейнеры не установлены. Версии пакетов окружения проверены отдельными
фикстурами, включая отказ при Env8/Env9 и повреждённых метаданных.

Полный набор из 32 основных RPM PHP 8.3, включая пакет php-fpm, отдельно
прошёл настоящую установку и возврат точных старых RPM. Работоспособность
проверялась в CLI и Apache; FPM как веб-сервер не испытывался и не входит
в поддерживаемый профиль установщика.

Для испытаний самого установщика использован поддерживаемый набор из
31 основного RPM без php-fpm и пять PECL-пакетов: APCu, Memcached,
igbinary, msgpack, ZIP. Они сохранены при обновлении. Проверены версия,
список расширений, отсутствие ошибок загрузки, функциональные операции
с OpenSSL, intl, XML и другими модулями в CLI и Apache.

При повторном `--auto-update` целевая версия не устанавливается заново
и Apache дополнительно не перезапускается. Для испытания восстановления
в тестовом контейнере удалён PHP CLI, а также старый файл URL сессии:
откат использует сохранённое описание сайта. После отката и его повторного
запуска исходный полный RPM-инвентарь восстановлен точно.

Два тестовых сайта имеют разные DocumentRoot; один расположен по пути
с пробелом через символическую ссылку. Для временной пробы проверены
отказ без токена (404), успешный запрос (200), повторный отказ (404),
удаление временных файлов, неизменность конфигурации Apache и пакетов.
Сайт с отключённым PHP отвергается; неоднозначный выбор без терминала
требует `--site`.

## Сборка PHP 8.3

Собран Remi SRPM PHP 8.3.36 на CentOS 7, GCC 4.8.5, OpenSSL 1.0.2,
с проверкой SHA-256 и подписи исходного архива PHP. Два локальных патча
обеспечивают совместимость нового кода с OpenSSL 1.0.2 и макросом
`strncmp` старой glibc. Подготовка исходников установщиком воспроизводит
spec и патчи фактической сборки байт в байт.

Проверены контрольные суммы, метаданные и зависимости всех 32 RPM и SRPM.
Дополнительные требования к символам libgcc, libxml2 и glibc удовлетворены
штатными библиотеками тестового CentOS 7; новые ABI библиотек не потребовались.
Точная разница опубликована в `RPM-REQUIRES-CHANGES.txt` выпуска.

Повторный штатный прогон PHP: 19 650 тестов, 11 395 PASS, 8 246 SKIP,
7 ожидаемых upstream XFAIL, 2 FAIL, предупреждений нет. Два сбоя относятся
к тексту ошибок OpenSSL 1.0.2 и Unicode-пути при локали C; результат
воспроизведён байт в байт на исходном PHP 8.3.8. Это не полностью зелёный
набор upstream-тестов. Дополнительный набор загружаемых расширений и
проверки уже установленных RPM описаны в `BUILD-INFO.txt` выпуска.

Исходный полный журнал rpmbuild был утрачен из-за ошибки редактирования
запущенной тестовой обвязки. Готовые пакеты сохранены без пересборки;
пять деревьев сборки повторно проверены `make`, штатные тесты запущены
заново с отдельным журналом, а все RPM проверены и испытаны после установки.
Ошибка и границы подтверждения подробно отражены в `BUILD-INFO.txt`.

## Публикация и совместимость

Публичные файлы находятся в репозитории `vitikevich-landau/bitrix-php-updater`.
Для проверки подписанных файлов используется прежний ключ с отпечатком
`A3D2CA1B007D523054CF4B718D37B52421640029`. Комплект PHP 8.2 сохраняется
без изменений. Подтверждение публичного скачивания, подписей и работы
`--auto-update` через GitHub публикуется в подписанном
[HTTPS-VALIDATION.txt](https://github.com/vitikevich-landau/bitrix-php-updater/releases/download/php-8.3.36-el7-r1/HTTPS-VALIDATION.txt)
вместе с выпуском. Этот отчёт формируется после публикации и поэтому
не включён в ранее подписанный манифест исходников; он имеет свою подпись.

Подписанные архивы отката первоначально содержат точные исходные комплекты
8.2.20-1.el7.remi и 8.3.8-1.el7.remi, x86_64, без epoch. Другие выпуски
требуют добавления их точных оригинальных RPM в подписанный архив
соответствующей ветки. При отсутствии комплекта отката установка прекращается.

## Что не подтверждают эти испытания

Контейнер не заменяет виртуальную машину клиента. `systemctl` заменён
тестовой обвязкой, которая действительно останавливает и запускает Apache;
сам systemd не испытывался. Не проверены работоспособность ядра и модулей
Битрикса, nginx перед Apache, реальная MySQL/MariaDB, cron/агенты, почта,
интеграции и нагрузка клиентского сайта. ODBC-тесты без внешней БД пропущены.
На клоне нужно проверить эти компоненты, обновление и откат, затем назначить
окно обслуживания. Целевой патч PHP не делает CentOS 7 поддерживаемой ОС.
