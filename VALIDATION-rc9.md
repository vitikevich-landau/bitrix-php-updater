## Настоящие Apache и RPM

В одноразовом CentOS 7 x86_64 использованы Apache 2.4.6/prefork/mod_php,
Bash 4.2, исходные Remi PHP 8.2.20 и подписанный комплект проекта
`php-8.2.35-el7-r1`. Обновлялись 31 основной пакет PHP без PHP-FPM;
установленные PECL-расширения сохранялись.

Подтверждено:

- обнаружение двух vhost, включая DocumentRoot через символьную ссылку и путь с пробелом;
- настоящие запросы без ключа / с ключом / без ключа: 404 / 200 / 404;
- отказ при выдаче PHP как текста и при неоднозначном выборе без терминала;
- неизменность конфигурации Apache и списка RPM после `--check-site`;
- `--setup-update`: скачивание закреплённого публичного ключа, запись auto-конфигурации;
- сохранность прежней конфигурации после неудачной настройки другого сайта;
- `--auto-update`: реальная установка 8.2.35 из локальной копии подписанного выпуска;
- повторное обновление не переустанавливает PHP и не перезапускает Apache;
- откат по сохранённому описанию сайта при отсутствующем `/usr/bin/php` и удалённом поле URL сессии;
- повторный откат и точное совпадение полного исходного набора RPM;
- работоспособность CLI и Apache/PHP до обновления, после него и после отката;
- успешные функциональные пробы ZIP, APCu, Memcached, igbinary и msgpack;
- отсутствие временных файлов во всех проверенных каталогах сайтов после операций.

При повторном прогоне rc9 RPM брались из локальной копии того же подписанного
выпуска; сетевое скачивание всего комплекта ранее проверено с rc8. В этом
прогоне реальная загрузка с GitHub проверена для публичного ключа.

## Границы результата

Это контейнерный стенд с настоящими RPM, PHP и Apache. Управление службой
Apache заменено тестовой обвязкой; полноценные systemd, nginx, Битрикс,
база данных и пользовательские модули не проверялись. Тест временного PHP
проверяет интерпретатор и нужные расширения, а не все функции сайта.

Перед рабочим сервером нужен прогон на его клоне. Поддерживаемый профиль
и покрытие архива старых RPM остались прежними. После SIGKILL или потери
питания мгновенное удаление невозможно: действует срок доступа, затем
следующая проверка пытается безопасно удалить подтверждённые остатки.
Изменённые или неполные артефакты требуют проверки администратором.
