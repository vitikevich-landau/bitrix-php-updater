# Проверки временного веб-теста

**Запускайте только в одноразовом контейнере. Эти тесты изменяют конфигурацию Apache, создают тестовые каталоги сайта, запускают Apache и намеренно прерывают процессы. На клиентском сервере их запускать нельзя.**

Требуется заранее подготовленный образ CentOS 7 x86_64 с Apache 2.4/prefork, mod_php 8.2, расширениями mysqli и mbstring, curl, coreutils/util-linux, Python 2.7 или совместимым `python`, штатным пользователем `nobody` (UID 99). Apache должен читать `/etc/httpd/conf.d/*.conf` и поддерживать PHP-файлы. Образ предоставляется разработчиком; тесты не скачивают зависимости.

Из корня репозитория, в Bash на Linux/WSL:

```bash
docker run --rm --pull never --network none \
  --security-opt no-new-privileges \
  --env BITRIX_DISPOSABLE_TEST=1 \
  --mount "type=bind,source=$PWD,target=/repo,readonly" \
  YOUR_CENTOS7_PHP82_IMAGE bash -c '
    set -e
    bash /repo/tests/managed-probe/test-probe.sh /repo/install.sh
    bash /repo/tests/managed-probe/test-directory-races.sh /repo/install.sh
  '
```

Не публикуйте порты контейнера и не подключайте каталоги работающего сайта. Репозиторий подключается только для чтения. Файловая система самого контейнера должна быть доступна для записи. `--rm` удаляет одноразовый стенд после завершения.

Без переменной `BITRIX_DISPOSABLE_TEST=1` сценарии отказываются работать. Если их фиксированные тестовые каталоги уже существуют, запуск также прекращается до изменений.

`test-probe.sh` использует настоящий Apache, PHP и curl. Проверяет закрытый доступ, неправильный ключ и X-Forwarded-For, отсутствие секрета в PHP/аргументах/окружении curl, отклонение кэша и неправильных ответов, срок действия, очистку после ошибок и сигналов, повторную очистку после SIGKILL, сохранение изменённых файлов и символических ссылок, переименование родительского каталога, коллизии имён и ошибки SELinux. Ошибки транспорта и кэш имитируются отдельной тестовой обвязкой.

`test-directory-races.sh` воспроизводит четыре подмены каталога сразу после его создания. Действия владельца сайта выполняются от непривилегированного `nobody`: каталог с символической ссылкой на файл root, ссылка на закрытый каталог root, переименование закрытого каталога root и переименование непустого каталога. Проверяется отказ до записи PHP-файла и HTTP-запросов; посторонние данные и права должны сохраниться.

Во время тестов сигналов ожидаются сообщения оболочки `Terminated`, `Hangup`, `Killed`. Успешные сценарии печатают `PASS`, итоговый код — 0. Это проверка механизма временного веб-теста; совместимость настоящего Битрикса, nginx, БД и пользовательских модулей проверяется отдельно на клоне сервера.
