# Регрессионные проверки

Запускайте из корня репозитория в одноразовых Docker-контейнерах. Команды ниже рассчитаны на Bash (Linux / WSL). Нужны заранее загруженные образы `centos:7` и `python:3.11-slim`; внутри тестов сеть отключена, репозиторий подключён только для чтения.

Проверки подписи и клиентской подготовки на Bash 4.2 / GnuPG 2.0 из CentOS 7:

```bash
docker run --rm --network none --read-only \
  --tmpfs /tmp:rw,nosuid,nodev,exec,size=64m \
  --tmpfs /root:rw,nosuid,nodev,exec,size=64m,mode=0700 \
  --env TMPDIR=/root \
  --mount "type=bind,source=$PWD,target=/repo,readonly" \
  centos:7 bash -c '
    set -e
    bash /repo/tests/test-publisher.sh /repo/install.sh
    bash /repo/tests/test-publisher-client.sh /repo/install.sh
  '
```

Проверки интерактивного меню и первичной настройки через псевдотерминал:

```bash
docker run --rm --network none --read-only \
  --tmpfs /tmp:rw,nosuid,nodev,exec,size=64m \
  --tmpfs /root:rw,nosuid,nodev,exec,size=64m,mode=0700 \
  --env TMPDIR=/root \
  --mount "type=bind,source=$PWD,target=/repo,readonly" \
  python:3.11-slim bash -c '
    set -e
    python -B /repo/tests/test-menu.py /repo/install.sh
    python -B /repo/tests/test-setup.py /repo/install.sh
  '
```

Каждый файл также запускается отдельно с путём к проверяемому `install.sh` первым аргументом. Успешный прогон печатает `PASS` и завершается с кодом 0; любой провал даёт ненулевой код.

| Файл | Что проверяет |
|---|---|
| `test-publisher.sh` | Реальные RSA-подписи манифестов, экспорт только публичного ключа, точные имена старых RPM, отказ при повреждённых входах и отсутствие частично опубликованного каталога. |
| `test-publisher-client.sh` | Передачу реально подписанного выпуска клиенту, выбор точных старых пакетов, необходимые новые модули, повторное использование подписанного подмножества, ошибки подписи/хеша/загрузки, защищённую конфигурацию и отказ до установки. |
| `test-menu.py` | Навигацию, значения по умолчанию, отмену, EOF и точные аргументы запуска выбранных действий. |
| `test-setup.py` | Закрепление хеша ключа, права файлов, символьные ссылки, отмену, проверку сайта и сохранность прежней конфигурации при ошибке. |

Shell-тесты создают временные тестовые RSA-ключи внутри контейнера; ключи выпуска не нужны и не используются. RPM представлены текстовыми фикстурами, системные службы, веб-проверка и установка заменены заглушками. Тест настройки подставляет фиктивный ключ и его хеш только в исполняемую тестовую копию функции. Файл `install.sh` не изменяется.

Каталоги фикстур находятся под закрытым `/root`: это позволяет проверять реальные ограничения владельца и прав без раннего отказа из-за общего `/tmp`. Отрицательные проверки подписи, подготовки и настройки сверяют причину отказа, а не только код завершения.

Эти проверки не подтверждают реальную установку/откат RPM, работу Apache и совместимость конкретного сайта. Для проверки выпуска нужен отдельный прогон обновления и отката на клоне BitrixVM с настоящими пакетами и сайтом.
