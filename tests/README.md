# Регрессионные проверки

Запускайте из корня репозитория в одноразовых Docker-контейнерах. Команды ниже рассчитаны на Bash (Linux / WSL). Нужны заранее загруженные образы `centos:7` и `python:3.11-slim`; внутри тестов сеть отключена, репозиторий подключён только для чтения.

Проверки подписи и клиентской подготовки на Bash 4.2 / GnuPG 2.0 из CentOS 7:

```bash
docker run --rm --network none --read-only \
  --tmpfs /tmp:rw,nosuid,nodev,exec,size=64m \
  --tmpfs /root:rw,nosuid,nodev,exec,size=64m,mode=0700 \
  --env TMPDIR=/root \
  --mount "type=bind,source=$PWD,target=/repo,readonly" \
  centos:7 bash -c '
    set -e
    bash /repo/tests/test-publisher.sh /repo/install.sh
    bash /repo/tests/test-publisher-client.sh /repo/install.sh
  '
```

Проверки меню через псевдотерминал, автоматической настройки без ввода
и передачи выбранного сайта между командами:

```bash
docker run --rm --network none --read-only \
  --tmpfs /tmp:rw,nosuid,nodev,exec,size=64m \
  --tmpfs /root:rw,nosuid,nodev,exec,size=64m,mode=0700 \
  --env TMPDIR=/root \
  --mount "type=bind,source=$PWD,target=/repo,readonly" \
  python:3.11-slim bash -c '
    set -e
    python -B /repo/tests/test-menu.py /repo/install.sh
    python -B /repo/tests/test-setup.py /repo/install.sh
    python -B /repo/tests/test-managed-integration.py /repo/install.sh
  '
```

Каждый файл также запускается отдельно с путём к проверяемому `install.sh` первым аргументом. Успешный прогон печатает `PASS` и завершается с кодом 0; любой провал даёт ненулевой код.

| Файл | Что проверяет |
|---|---|
| `test-publisher.sh` | Реальные RSA-подписи манифестов, экспорт только публичного ключа, точные имена старых RPM, отказ при повреждённых входах и отсутствие частично опубликованного каталога. |
| `test-publisher-client.sh` | Передачу реально подписанного выпуска клиенту, выбор точных старых пакетов, необходимые новые модули, повторное использование подписанного подмножества, ошибки подписи/хеша/загрузки, защищённую конфигурацию и отказ до установки. |
| `test-menu.py` | Навигацию, значения по умолчанию, отмену, EOF, запуск `--check-site` без вопроса об URL и автоматическую проверку при пустом URL ручной установки. |
| `test-setup.py` | Настройку без терминала и ручного URL, явный/сохранённый выбор сайта, повторный выбор в терминале, закрепление хеша ключа, права и символьные ссылки, отказы выбора/проверки, сохранность прежней конфигурации при ошибке. |
| `test-managed-integration.py` | Конфигурации auto и прежние URL, передачу точного выбора без повторного запроса, `--site`, отсутствие временного теста в read-only `--check`, запись описания сайта и откат без PHP/discovery до восстановления. |

Shell-тесты создают временные тестовые RSA-ключи внутри контейнера; ключи выпуска не нужны и не используются. RPM представлены текстовыми фикстурами, системные службы, веб-проверка и установка заменены заглушками. Тесты настройки и интеграции подставляют фиктивный ключ и его хеш только в исполняемую тестовую копию функции. Обнаружение сайта и HTTP-проба заменены на границе вызова, а запись конфигурации и её защищённые файловые проверки выполняются настоящим кодом. Файл `install.sh` не изменяется.

Каталоги фикстур находятся под закрытым `/root`: это позволяет проверять реальные ограничения владельца и прав без раннего отказа из-за общего `/tmp`. Отрицательные проверки подписи, подготовки и настройки сверяют причину отказа, а не только код завершения.

Перечисленные выше проверки используют заглушки и не подтверждают реальную установку/откат RPM, работу временного PHP-файла либо совместимость конкретного сайта. Проверки обнаружения сайтов и настоящей HTTP-пробы описаны ниже; прогон обновления и отката на клоне BitrixVM остаётся отдельным этапом.

## Проверки автоматического поиска сайтов

Эти тесты запускаются из корня репозитория в одноразовых контейнерах. Нужны Docker и заранее загруженные образы `centos:7` и `python:3.11-slim`. Команды рассчитаны на Bash в Linux/WSL. Каталог тестов должен находиться в `tests/` рядом с `install.sh` в корне репозитория.

```bash
docker run --rm --network none --read-only \
  --tmpfs /tmp:rw,nosuid,nodev,exec,size=64m \
  --tmpfs /root:rw,nosuid,nodev,exec,size=64m,mode=0700 \
  --env TMPDIR=/root \
  --mount "type=bind,source=$PWD,target=/repo,readonly" \
  centos:7 bash -c '
    set -e
    bash /repo/tests/test-managed-discovery.sh /repo/install.sh
    bash /repo/tests/test-managed-startup.sh /repo/install.sh
  '

docker run --rm --network none --read-only \
  --tmpfs /tmp:rw,nosuid,nodev,exec,size=64m \
  --tmpfs /root:rw,nosuid,nodev,exec,size=64m,mode=0700 \
  --env TMPDIR=/root \
  --mount "type=bind,source=$PWD,target=/repo,readonly" \
  python:3.11-slim python -B /repo/tests/test-managed-selection.py /repo/install.sh
```

- `test-managed-discovery.sh` проверяет основной сайт, виртуальные хосты, алиасы, кавычки и пробелы в путях, локальные порты, HTTPS, наследование DocumentRoot и отказ при неоднозначной/неподдержанной конфигурации. Ответы Apache заменены фиксированными примерами; парсер, разрешение каталогов и выбор сайта выполняются настоящими функциями установщика.
- `test-managed-startup.sh` проверяет разрешённые стандартные аргументы Apache и отказ при альтернативной конфигурации, дополнительных директивах и неизвестных параметрах.
- `test-managed-selection.py` проверяет выбор через псевдотерминал, отмену пустым вводом/EOF, неверный номер и отсутствие запроса в unattended-режиме. Только список обнаруженных сайтов заменён фикстурой.

Все тесты принимают путь к полному `install.sh`, извлекают определения функций до диспетчера команд и проверяют именно их. Отдельный файл с копией реализации не используется. Изменения установщика, сайтов, служб и пакетов не выполняются. Эти тесты не заменяют проверку на настоящем Apache и клоне BitrixVM.
